## Grammar-exact bounded correction

The recovery does not add another quote heuristic. It replaces the
hand-written YAML quote/comment/indicator scanner with the token API from
exactly pinned `unsafe-libyaml` 0.2.11, the already-locked parser underneath
`serde_yaml` 0.9.34. The dependency was already present and reviewed in the
locked graph; declaring it directly in the application and fuzz manifests
adds no package, version, license, or download, while making the security
boundary's actual parser dependency explicit.

The scanner is initialized in stable heap storage because its input handler
retains the parser address. Parser and token allocations have unique RAII
guards and are deleted on every success or policy-error return. The borrowed
input outlives parser deletion. Only the scalar union arm selected by an exact
scalar token is read, and scan, parse, and load APIs are never mixed on one
parser.

The boundary now performs these ordered checks:

1. reject empty, oversized, or non-UTF-8 input before scanner allocation;
2. incrementally tokenize with the same YAML grammar used for deserialization;
3. reject exact anchor or alias tokens before any `serde_yaml::Value` can be
   constructed or an alias resolved;
4. bound scalar bytes, exact flow depth, combined block/flow syntax depth, and
   structural tokens while each owned token is live;
5. deserialize only the accepted stream to `serde_yaml::Value`; and
6. retain the independent iterative value-tree limits for depth, nodes,
   collection entries, and decoded scalar bytes before typed `PatchState`
   construction.

This makes quote, comment, plain-scalar, and literal/folded block-scalar
classification grammar-exact and keeps the admission path linear in the
bounded input size. It also preserves the original fail-closed rule that
patches are trees and therefore have no need for YAML graph indirection.
