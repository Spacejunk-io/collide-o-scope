## Root cause and correction

`robocopy` returns codes `0` through `7` for successful or nonfatal copy
outcomes. `Copy-SeedTree` correctly rejected only values `>= 8`, but it left an
accepted return code of `1` in process-wide `$LASTEXITCODE`. The remaining step
used only PowerShell and .NET operations, so GitHub Actions inherited that `1`
and reported a failed step despite the successful verified copies.

The correction captures the native status immediately, throws on `>= 8`, and
only after the guard succeeds resets `$global:LASTEXITCODE` to zero. The static
release-policy checker requires those operations once and in order, and hostile
mutations reject a forged zero capture, a weakened threshold, or a nonzero
reset. A Windows process-scope regression must additionally prove that accepted
codes `1` and `7` become caller-visible zero while code `8` throws.

The release version advances to `1.7.1` in `Cargo.toml`, the root `Cargo.lock`
package, both macOS bundle version fields, and the release workflow dispatch
default. Asset names, release URL, tag source ref, certificate identity, and
final-receipt names derive from the tag and therefore require no fixed-name
rewrite.
